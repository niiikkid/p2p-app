# P2P Bridge

> Android-клиент для P2P-процессинга: собирает входящие SMS и push-уведомления, хранит локальную историю и передаёт сообщения на сервер.

## Возможности

- Принимает входящие SMS.
- Получает push-уведомления через системный доступ к уведомлениям Android.
- Позволяет выбрать источники: отправителей SMS и приложения.
- Сохраняет историю сообщений локально на устройстве.
- Отправляет данные на внешний сервер с токеном доступа.
- Не теряет сообщения при временном сбое сети: ставит их в очередь и повторяет отправку.
- Защищает от повторной отправки одинаковых сообщений.
- Периодически проверяет связь с сервером и совместимость версии приложения.

## Как это работает

1. При первом запуске приложение запрашивает доступ к SMS, уведомлениям и работе без ограничений батареи.
2. После подключения устройства по токену можно включить автоматику.
3. Приложение принимает SMS и push-уведомления только от выбранных источников.
4. Сообщение попадает в локальную историю и отправляется на API.
5. Если сервер недоступен, сообщение остаётся в очереди до следующей попытки.

> Приложение обрабатывает только те SMS и уведомления, к которым пользователь предоставил доступ в настройках Android.

## Стек

- **Kotlin 2.0.0** и **JDK 17**
- **Jetpack Compose** + Material 3
- **Hilt** для внедрения зависимостей
- **Room** для локальной истории и очереди
- **DataStore** для настроек
- **WorkManager** для повторных попыток
- **OkHttp** для HTTP-запросов

## Требования

- Android Studio с поддержкой Android Gradle Plugin 8.5.1
- JDK 17
- Устройство или эмулятор с Android 8.0+ (API 26+)
- Доступный сервер P2P-процессинга

## Быстрый старт

```bash
git clone https://github.com/niiikkid/p2p-app.git
cd p2p-app
cp .env.example .env
```

Откройте `.env` и укажите адрес своего сервера:

```dotenv
API_HOST=https://your-server.example
APP_TITLE=P2P Bridge
APP_VERSION=1.0.0
NOTIFICATION_DEBUG_MODE=false
```

Затем откройте проект в Android Studio и запустите приложение на устройстве.

### Сборка из терминала

```bash
./gradlew assembleDebug
```

## Настройка приложения

После установки:

1. Разрешите приём и чтение SMS.
2. В системных настройках Android включите доступ приложения к уведомлениям.
3. Разрешите работу без оптимизации батареи, чтобы Android не останавливал сервис в фоне.
4. Нажмите **«Подключить устройство»**, введите токен от сервера и сохраните его.
5. Включите автоматику и выберите нужные источники сообщений.

## Конфигурация

Переменные можно передать через окружение, файл `.env` в корне проекта или `local.properties`. Приоритет: окружение → `.env` → `local.properties`.

| Переменная | Обязательна | Описание |
| --- | :---: | --- |
| `API_HOST` | Да | Базовый адрес сервера API, например `https://your-server.example` |
| `APP_TITLE` | Нет | Название приложения. По умолчанию — `P2P Bridge` |
| `APP_VERSION` | Нет | Версия, которую приложение передаёт серверу. По умолчанию — `1.0.0` |
| `NOTIFICATION_DEBUG_MODE` | Нет | Включает диагностические данные уведомлений. По умолчанию — `false` |

Файл `.env` не попадает в Git. Не добавляйте в репозиторий реальные токены, адреса закрытых серверов и ключи подписи.

## Серверное API

Базовый адрес задаётся через `API_HOST`. Приложение использует следующие пути:

| Метод | Путь | Назначение |
| --- | --- | --- |
| `POST` | `/api/app/device/connect` | Подключение устройства по токену |
| `GET` | `/api/app/device/ping` | Проверка связи и версии приложения |
| `POST` | `/api/app/sms` | Передача SMS или push-уведомления |

Для запросов используется заголовок `Access-Token`; при отправке сообщения также передаётся `Idempotency-Key`, чтобы не создать дубликаты.
